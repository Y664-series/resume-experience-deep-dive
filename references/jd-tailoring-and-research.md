# JD 定制与研究

## 触发与授权

仅在用户希望针对岗位定制时启动本流程。

- 接收 JD；若只有岗位链接，读取链接内容。
- 询问目标公司和岗位名称。
- 在联网研究公司、行业或公开方法前，取得用户明确同意。
- 用户不同意时，仅依据 JD 和经历母档继续。
- 不要把是否联网与是否能完成定制绑定。

## JD 解析

提取并区分：

- 核心工作任务
- 必备能力与经验
- 加分项
- 行业和业务场景
- 关键词与表达风格
- 可合理推断但未明示的岗位重点

不要把公司宣传语直接当作真实工作要求。

## JD—事实映射

建立映射表：

| JD 要求 | 匹配等级 | 母档证据 | 是否需追问 | 使用建议 |
|---|---|---|---|---|

匹配等级：

- **强匹配**：存在直接事实、个人行动和结果支撑。
- **可迁移**：业务场景不同，但底层能力和方法相通。
- **弱匹配**：只有间接证据，需要追问才能判断。
- **缺失**：母档没有依据，只报告差距。

对弱匹配项提出最少的必要追问。对缺失项不得填入无依据关键词或改造历史事实。

## 公司与行业研究

用户明确同意后，按优先级使用：

1. 公司官网、产品页面和官方招聘页
2. 公司官方公开材料和可信行业资料
3. 可信从业者公开分享
4. 其他来源仅作为线索

研究笔记必须分为：

- JD 明示信息
- 公司公开事实及来源
- 行业通用认识及来源
- Agent 推断

公司资料不足时，不推断“公司调性”。不同来源冲突时，指出冲突和各自来源。

## 外部方法论研究

用户明确同意后，可搜索同岗位、同业务场景或同行业公开方法，用于：

- 给用户零散做法提供参照结构。
- 对比行业常见流程与用户实际路径。
- 补充复盘维度。
- 形成“如果重做”的改进建议。
- 解释跨行业能力迁移。

严格区分：

1. 用户当时真实使用的方法
2. Agent 根据真实行动事后归纳的方法
3. 公开资料中的外部方法
4. 用户未来可以尝试但尚未验证的方法

未经用户提供事实并确认，不得把外部方法移动到历史事实层，也不得暗示用户当时已经采用。

## 定制写作

1. 以强匹配事实为主线。
2. 选择最能证明核心岗位要求的 2–5 条具体事项。
3. 可迁移能力需解释底层相似性，不只堆关键词。
4. 根据事实关系选择项目型、罗列型或混合型。
5. 调整信息顺序、颗粒度和用词，但不改变事实。
6. 契合公司业务语境，不模仿宣传口号。
7. 保留真实弱项，不追求表面上的全面匹配。

同时生成不进入简历正文的定制说明：

- 使用了哪些母档事实。
- 分别对应哪些 JD 要求。
- 使用了哪些公司或行业公开事实。
- 哪些内容属于 Agent 推断。
- 为什么采用当前结构和顺序。
- 哪些素材被舍弃。
- 仍存在哪些能力缺口。

## 失败与降级

- 联网失败：退回仅依据 JD 定制。
- JD 内容不完整：说明缺失部分，依据可见内容继续。
- 公司名称存在歧义：先请用户确认主体。
- 经历与 JD 匹配度低：如实给出差距和可迁移项，不虚构。
- 公开资料相互冲突：保留冲突和来源，不替用户选定未经证实的事实。
- 外部方法只有二手转述：将其作为线索，优先寻找原始或权威来源。
