# 访谈框架

## 访谈节奏

把访谈设计成耐心的深度对话，而不是一次性问卷。

- 每轮通常只问一个核心问题。
- 只有多个子问题高度相关且容易一起回答时，才合并为不超过三个短问题。
- 先简短复述已知事实，再指出本轮需要补齐的缺口。
- 根据新回答动态调整后续问题，不机械执行固定顺序。
- 对关键问题追问到底，对不影响最终表达的细节及时停止。
- 定期用一小段话总结进展，让用户知道已经挖出了什么。

## 事实账本

持续维护以下字段：

| 字段 | 需要记录的内容 |
|---|---|
| 基本信息 | 标题、组织、时间、角色、团队 |
| 业务背景 | 服务对象、问题、业务模式、项目位置 |
| 目标与约束 | 目标、成功标准、资源、时间、规则 |
| 个人贡献 | 任务、行动、判断、决策权、影响链路 |
| 协作 | 相关方、分歧、推动方式、取舍 |
| 结果与证据 | 定量或定性结果、口径、来源、可信度 |
| 挑战与复盘 | 困难、失败、异常、重做方案 |
| 方法沉淀 | 当时方法、事后归纳、复用与边界 |
| 未决事项 | 缺口、矛盾、可回查位置 |

每条信息标记为“已确认事实”“有依据的估算”“Agent 推断”“存在矛盾”“尚待补充”或“不适用”。

下一问优先级从高到低为：

1. 可能导致事实失真的矛盾。
2. 无法区分个人与团队的归因。
3. 支撑核心结果所需的证据。
4. 影响经历主线的目标、行动和判断。
5. 有助于面试的挑战、复盘与方法。
6. 仅用于丰富背景的次要细节。

## 核心必问

根据已有材料跳过已明确回答的内容。

### 背景、团队与角色

- 这段经历发生在什么业务或项目背景下？
- 团队如何分工？你承担什么角色？
- 你能独立决定什么，哪些内容需要他人确认？
- 面试官不了解这个业务时，最少需要知道哪些背景？

### 目标与个人任务

- 项目真正要解决的问题是什么？成功意味着什么？
- 你负责哪些任务？为什么这些任务由你负责？
- 每项任务如何影响整体目标，而不是只完成局部工作量？
- 哪些结果能够明确归因给你，哪些属于团队共同成果？

### 行动与判断

- 你具体做了哪些关键动作，先后顺序是什么？
- 为什么选择这条路径？还考虑过哪些方案？
- 当时有哪些资源、时间、技术或协作约束？
- 哪个判断最能体现你的专业能力？

### 挑战与复盘

- 最大困难或不确定性是什么？
- 你如何定位问题、推动解决并验证结果？
- 哪些地方没有达到预期？
- 如果重新做一次，哪些路径会保留，哪些会改变？为什么？

## 条件触发追问

### 出现协作、分歧或推动

- 各方目标分别是什么？
- 分歧具体发生在哪个决策点？
- 你用什么数据、用户反馈、原型或机制推动共识？
- 最终方案做了哪些取舍？谁承担了什么成本？

### 出现“主导”“负责”“推动”

- 你亲自完成了哪些动作？
- 你拥有最终决策权，还是负责提出方案和协调执行？
- 如果去掉你的贡献，项目最可能受到什么影响？
- “主导”“负责”“参与”“协助”中哪个词最准确？

### 出现行业洞察

只在用户确有行业接触或进入 JD 定制阶段时追问：

- 该行业的主要价值链和增长驱动是什么？
- 你观察到哪些变化？依据是什么？
- 过往行业与目标行业有哪些相同能力和关键差异？

## 数据与证据核验

用户提供“提升 XX%”“降低 XX”“覆盖 XX 人”等结果时，逐层核验：

1. **结果动作链**：哪些具体动作促成该数据变化？
2. **基线与目标**：原始值、目标值和目标制定依据是什么？
3. **指标口径**：分子、分母、时间范围、样本范围是什么？
4. **比较方式**：同比、环比、前后测、实验组对照组或其他方式？
5. **归因边界**：同期还有哪些因素可能影响结果？
6. **异常情况**：哪些数据不符合预期？如何分析和处理？
7. **指标选择**：指标由谁选定？为什么能反映当时目标？用户参与了什么？
8. **证据来源**：后台、周报、复盘、验收材料或他人确认？

无法完整核验时降低表达强度，并在母档记录限制。

## 无量化结果

不要把没有数字等同于没有价值。按以下顺序处理：

1. 判断是没有数据，还是用户暂时想不起来。
2. 提示回查后台、周报、复盘、聊天记录、验收材料或相关同事。
3. 寻找替代证据：
   - 按期交付或通过验收
   - 用户、客户或团队采用
   - 质量改善或返工减少
   - 决策、流程或协作方式变化
   - 风险规避
   - 在复杂约束下完成关键产出
4. 允许有依据的区间估算，记录估算方法、依据和可信度。
5. 只有用户确认后，才在简历使用“约”“超过”等限定词。
6. 仍无数字时，用具体的“行动＋产出＋价值”描述。

## 挑战、失败与复盘

主动但不审判地询问：

- 什么没有按计划发生？
- 哪个假设后来证明错误？
- 是否存在延期、返工、低采用或未达指标？
- 当时如何发现问题并止损？
- 复盘后形成了哪些新的判断或流程？

负面信息默认进入母档和面试准备，不自动写入简历。

## 方法论归纳

不要强迫用户提供宏大方法论。检查清单、判断原则和稳定工作习惯都可以成为真实沉淀。

归纳步骤：

1. 找出用户反复使用的动作或判断维度。
2. 按实际先后关系整理为步骤、清单或决策规则。
3. 使用朴素名称，避免包装式术语。
4. 指出支撑该归纳的具体事实。
5. 标记形成时间：
   - 当时已形成并使用
   - 事后复盘归纳
   - 尚未实际验证的改进设想
6. 说明适用条件、局限和是否复用。
7. 请用户确认内容与名称。

## 结束条件

仅当以下条件全部满足，或用户明确表示无法继续补充时，进入事实确认：

- 背景、目标、角色、行动、判断、协作、结果和复盘等适用维度已有信息。
- 关键模糊表述已经核验。
- 个人贡献和团队成果能够区分。
- 核心结果有证据或明确的可信边界。
- 矛盾已经解决或被清楚保留。
- 已询问“还有没有你认为重要、但我们尚未谈到的内容？”

## 暂停、恢复与事实修正

暂停时输出：

- 已确认事实摘要
- 当前估算和推断
- 未解决矛盾
- 尚缺信息
- 下一问建议

恢复时从尚未解决的最高优先级缺口继续。

用户修正事实时：

1. 更新事实账本。
2. 找出依赖旧事实的结果、方法论和简历表达。
3. 明确告诉用户哪些内容受到影响。
4. 重新确认受影响部分。
