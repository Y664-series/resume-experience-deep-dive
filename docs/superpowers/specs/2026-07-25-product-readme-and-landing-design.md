# 产品 README 与 Landing Page 设计

## 目标

将 `resume-experience-deep-dive` 从“可安装的 Skill 文件夹”升级为一个容易理解、愿意尝试、可以传播的开源产品，同时不改变 Skill 的运行逻辑。

## 受众与页面任务

- 受众：准备求职、但不知道如何讲清一段经历的中文用户。
- README 的任务：让开发者或 Codex 用户在三分钟内理解、安装并触发 Skill。
- Landing Page 的任务：让非技术用户在一分钟内理解产品价值，并前往 GitHub 安装。

## 内容架构

README 借鉴参考项目的高信息效率，但只复用结构方法，不复制文案：

1. 一句话定位与 Banner
2. 三类入口
3. 核心产出
4. 工作流程
5. 三条产品原则
6. 无量化结果时的处理方式
7. 安装、触发示例与目录结构

Landing Page 使用同一套叙事：

1. Hero：把“我好像做过一些事”变成可验证的经历材料
2. 三类入口：完整简历、单段描述、零散回忆
3. 核心演示：模糊描述经过追问，转化为事实账本与简历 bullet
4. 三类产出：经历母档、面试记忆锚点、JD 定制稿
5. 真实性边界
6. 安装 CTA 与 GitHub 链接

## 视觉方向

- 背景：纸张白 `#F7F7F2`
- 主文字：墨黑 `#171717`
- 事实标注：蓝色 `#2458E6`
- 待确认与风险：红色 `#E04444`
- 辅助线：铅笔灰 `#C9C9C2`
- 字体：中文无衬线正文搭配手写感标题点缀，正文始终保持清晰。
- 签名元素：一条“追问线”连接模糊经历、事实账本与简历 bullet，像面试官在纸面上连续批注。

Banner 保留用户提供的“小熊递简历”形象与朴素手绘气质，扩展为横版构图；不拉伸原始位图，不添加复杂写实元素。

## 页面实现

- 单页、静态、响应式。
- 使用 Sites 标准项目结构。
- 不包含登录、表单提交、数据库或用户数据上传。
- 主要 CTA 指向 GitHub 仓库。
- 尊重键盘焦点与 reduced-motion。

## 验收标准

- README 在 GitHub 中能直接理解入口、流程、产出和安装方式。
- Landing Page 在桌面与移动端均可读。
- Banner 与页面视觉一致。
- 所有产品描述与实际 Skill 能力一致，不承诺不存在的功能。
- 构建成功，网站公开部署，GitHub 分支包含全部源文件。
